1. THE BIG PICTURE
========================================================================================

WHAT ARE WE TRYING TO ACHIEVE?
------------------------------

We want a repeatable method for estimating whether a customer will renew.

    Known usage + known renewal result
                    |
                    v
           +------------------+
           | LEARNING PROCESS |
           +---------+--------+
                     |
                     v
           Probability of renewal
                     |
                     v
        Apply decision threshold (such as 0.50)
                     |
              +------+------+
              |             |
              v             v
          Predict YES    Predict NO

WHAT IS CLASSIFICATION?
-----------------------

Classification is supervised learning used to predict a CATEGORY or CLASS.

    Input information                   Categorical output
    -----------------------------------------------------------------
    Customer usage history       --->   Renew / Not Renew
    Email words                  --->   Spam / Not Spam
    Transaction details         --->   Fraud / Legitimate
    Medical measurements        --->   Condition / No Condition
    Product photograph          --->   Defective / Acceptable

Our output is one of two categories, so this is a BINARY CLASSIFICATION problem.

CLASSIFICATION VERSUS REGRESSION
--------------------------------

    +----------------------+----------------------+----------------------+
    | Question             | Regression           | Classification       |
    +----------------------+----------------------+----------------------+
    | What is predicted?   | A numerical amount   | A category           |
    | Example              | Price = 84.5 lakh    | Renewal = Yes         |
    | Typical final output | Number               | Class and probability|
    | Main evaluation      | Size of errors       | Correct class counts |
    +----------------------+----------------------+----------------------+

FUNCTIONAL VIEW OF MACHINE LEARNING
-----------------------------------

TRAINING:

    Customer examples with answers ---> Learning algorithm ---> Model parameters

INFERENCE / PREDICTION:

    New customer's usage ---> Trained parameters ---> Probability ---> Class

EVALUATION:

    Predicted class + actual class ---> Confusion matrix ---> Trust decision

THE COMPLETE LOOP
-----------------

    +---------+   +---------+   +-------+   +-------+   +----------+
    | DEFINE  |-->| PREPARE |-->| TRAIN |-->| TEST  |-->| USE AND  |
    | PROBLEM |   | DATA    |   | MODEL |   | MODEL |   | MONITOR  |
    +---------+   +---------+   +---+---+   +---+---+   +----------+
                                      |           |
                                      +<--Improve-+

*** A classifier learns a statistical tendency. It does not discover a perfect rule. ***

2. THE REAL-WORLD PROBLEM
========================================================================================

SCENARIO
--------

A software company sells a monthly subscription. Before each customer's renewal
date, the company wants an early indication of whether that customer is likely to
renew.

For this first learning exercise, the company uses only one input:

    Average Weekly Product Usage Hours

It predicts one output:

    Renewed Subscription: Yes or No

PROBLEM STATEMENT
-----------------

    "Using average weekly usage hours, estimate the probability that a customer
     will renew, and classify the customer as Yes or No using a chosen threshold."

INPUT AND OUTPUT
----------------

    +-----------------------------+       +-----------------------------+
    | INPUT FEATURE (X)           |       | TARGET / LABEL (y)          |
    | Weekly usage hours          | ----> | Renewed? 1=Yes, 0=No        |
    +-----------------------------+       +-----------------------------+

WHY THIS IS A GOOD FIRST EXAMPLE
--------------------------------

  - subscription usage is easy to understand;
  - the outcome has two clear classes;
  - one feature allows every calculation to be followed manually;
  - the probability curve can be visualized;
  - realistic exceptions demonstrate that prediction is uncertain;
  - the same workflow later applies to larger classification projects.

HOW THE RESULT COULD BE USED
----------------------------

The prediction could support:

  - estimating expected renewals;
  - prioritizing customer-success conversations;
  - planning retention campaigns;
  - identifying predictions that require human review.

The prediction should NOT automatically decide how a customer is treated. A real
system needs more features, fairness checks, privacy controls, monitoring, and a
clear human decision process.

SUCCESS CRITERIA FOR THIS EXERCISE
----------------------------------

The learned classifier should:

  1. beat a simple baseline on untouched test customers;
  2. return understandable renewal probabilities;
  3. make a useful trade-off between false positives and false negatives;
  4. remain explainable in plain language;
  5. expose uncertainty instead of pretending every answer is certain.

FEATURE VERSUS TARGET
---------------------

    Feature X = information available before making the prediction
    Target  y = answer the model is expected to learn to predict

    X = Weekly_Usage_Hours
    y = Renewed_Subscription

relationship with renewal.

WHY INCLUDE BOTH 0/1 AND YES/NO?
--------------------------------

    Renewed_Subscription makes manual mathematics convenient.
    Renewal_Label makes the file easy for people to read.

These two columns describe the SAME outcome. They are not two independent inputs.

[CRITICAL]
----------

Renewal_Label must never be used as an input feature because it reveals the target.
That would be target leakage: the model would receive the answer it is meant to
predict.

---------------------------------

15 usage hours.

That is intentional. Real behavior is influenced by factors not present here:

  - price sensitivity;
  - product satisfaction;
  - team changes;
  - alternative products;
  - customer support experience;
  - budget and timing.

The model must learn a tendency, not memorize a simplistic rule.

4. ESSENTIAL CLASSIFICATION VOCABULARY
========================================================================================

OBSERVATION / SAMPLE / ROW
--------------------------

One entity in the dataset. Here, one observation is one customer.

FEATURE (X)
-----------

Input information used for prediction. Here, X is weekly usage hours.

TARGET / LABEL (y)
------------------

The correct historical answer. Here, y is renewed or did not renew.

CLASS
-----

One possible category of the target:

    Class 1 = Yes, renewed
    Class 0 = No, did not renew

POSITIVE AND NEGATIVE CLASS
---------------------------

By convention in this guide:

    Positive class = 1 = Yes
    Negative class = 0 = No

"Positive" is a mathematical name. It is not a moral judgment.

BINARY CLASSIFICATION
---------------------

A problem with exactly two possible classes.

MULTICLASS CLASSIFICATION
-------------------------

A problem with more than two classes, such as Basic / Standard / Premium.
This guide focuses exclusively on binary classification.

MODEL PARAMETER
---------------

A value learned from training data. Logistic regression learns:

    b0 = intercept
    b1 = coefficient for weekly usage hours

HYPERPARAMETER
--------------

A setting chosen outside the learning process, such as regularization strength.
The classification threshold is a decision setting, not a learned coefficient.

LOGIT / WEIGHTED SCORE (z)
--------------------------

An intermediate score produced by the linear part of logistic regression:

    z = b0 + b1*x

The score can be any number from negative infinity to positive infinity.

SIGMOID FUNCTION
----------------

A function that converts the unrestricted score z into a value from 0 to 1:

                     1
    Probability = ---------
                  1 + e^(-z)

PROBABILITY
-----------

A number between 0 and 1 representing estimated likelihood.

    0.10 = estimated 10% renewal probability
    0.50 = estimated 50% renewal probability
    0.90 = estimated 90% renewal probability

THRESHOLD
---------

A cutoff that converts probability into a class.

    If probability >= 0.50, predict Yes.
    If probability <  0.50, predict No.

PREDICTED CLASS
---------------

The final Yes/No decision after applying the threshold.

CONFUSION MATRIX
----------------

A 2-by-2 table that counts correct and incorrect predictions by type.

    TP = True Positive     Predicted Yes, actual Yes
    TN = True Negative     Predicted No,  actual No
    FP = False Positive    Predicted Yes, actual No
    FN = False Negative    Predicted No,  actual Yes

LOG LOSS
--------

A training measure that rewards confident correct probabilities and strongly
penalizes confident wrong probabilities. Lower is better.

CALIBRATION
-----------

Whether predicted probabilities match real frequencies. Among many customers
given approximately 0.70 probability, about 70% should renew in a well-calibrated
model.

INFERENCE
---------

Using the already trained model to predict an outcome for new data.

[CHECKPOINT]
------------

Can you explain this distinction?

    Probability: 0.713
    Threshold:   0.500
    Class:       Yes

The probability is the model's graded estimate. The class is a decision created
by comparing that estimate with the threshold.

6. STEP 1 — FRAME THE PROBLEM
========================================================================================

A clear prediction question prevents later confusion.

1. WHAT DOES ONE ROW REPRESENT?
-------------------------------

One customer approaching a subscription renewal decision.

2. WHAT INFORMATION IS AVAILABLE?
---------------------------------

Average weekly usage hours measured before the renewal outcome.

3. WHAT IS THE TARGET?
----------------------

Whether the customer renewed:

    1 = Yes
    0 = No

4. WHEN IS THE PREDICTION MADE?
-------------------------------

Before the renewal outcome is known.

5. WHAT KIND OF ML PROBLEM IS THIS?
-----------------------------------

    Is there a known target?                 YES -> Supervised learning
    Is the target a number or a category?    CATEGORY
    How many categories?                     TWO

    Final answer: Binary supervised classification

6. WHAT IS THE PREDICTION UNIT?
-------------------------------

One probability and one class per customer.

7. HOW WILL SUCCESS BE MEASURED?
--------------------------------

We will compare the model with a baseline and calculate:

  - confusion matrix;
  - accuracy;
  - precision;
  - recall;
  - F1 score;
  - specificity;
  - test log loss.

8. WHAT ARE THE COSTS OF ERRORS?
--------------------------------

If Yes is the positive class:

    False Positive:
    Model predicts renewal, but customer does not renew.
    Possible cost: the company misses a needed retention conversation.

    False Negative:
    Model predicts no renewal, but customer actually renews.
    Possible cost: unnecessary outreach or incentive expense.

Which error is worse depends on the real business action. That decision later
influences the probability threshold.

[OUTPUT]
--------

A precise, measurable classification problem with a defined prediction time,
target, positive class, and business use.

7. STEP 2 — COLLECT AND UNDERSTAND THE DATA
========================================================================================

WHERE COULD REAL DATA COME FROM?
--------------------------------

    +------------------+     +------------------+     +------------------+
    | PRODUCT EVENTS   |     | SUBSCRIPTIONS    |     | CUSTOMER RECORDS |

QUESTIONS TO ASK BEFORE MODELING
--------------------------------

  - How exactly is a usage hour calculated?
  - Is usage measured before the renewal date?
  - Is one row one customer or one subscription period?
  - Are renewals consistently recorded?
  - Are canceled, paused, and failed-payment accounts treated consistently?
  - Does the sample represent future customers?
  - Are privacy and consent requirements satisfied?

DATA LINEAGE
------------

For every column, know:

    Source ---> Definition ---> Collection time ---> Transformation ---> Owner

If the meaning of a field is unclear, the model cannot make that meaning clearer.

REPRESENTATIVENESS
------------------

Training data should resemble the population on which predictions will be made.

Possible mismatches:

  - training on annual plans, predicting monthly plans;
  - training on one country, predicting another;
  - training during a free promotion, predicting normal months;
  - excluding customers who left before measurement completed;
  - measuring usage differently in the future.

LABEL QUALITY
-------------

The target must describe the intended business event.

    Correct: renewal completed within the defined renewal window
    Ambiguous: account was "active" at some unspecified time

A classifier cannot be more reliable than the labels used to teach it.

------------------------

Ask separately for feature and target:

    Missing usage?
        Investigate tracking failure, estimate carefully, or exclude the row.

    Missing renewal result?
        The row cannot supervise training until the outcome is known.

Never silently convert a missing value into zero. Zero usage and unknown usage

8.3 CHECK DUPLICATES

If the same customer-period appears twice, it can receive extra influence during

--------------------------

Examples of suspicious values:

    -4 hours per week    impossible
    900 hours per week   impossible
    0.5 entered as 50    unit or percentage error

The learning dataset uses whole weekly hours from 2 to 20.

8.5 CHECK TARGET CONSISTENCY
----------------------------

    Renewed_Subscription = 1 must match Renewal_Label = Yes
    Renewed_Subscription = 0 must match Renewal_Label = No

-------------------------------------

Customer_ID is retained for tracking rows, but excluded from model input.

8.7 PREVENT TARGET LEAKAGE
--------------------------

BAD FEATURE EXAMPLES:

  - final renewal receipt number;
  - payment captured after renewal;
  - Renewal_Label itself;

11. STEP 6 — CREATE A BASELINE

WHAT IS A BASELINE?
-------------------

A baseline is a simple reference rule that a useful classifier should beat.

MAJORITY-CLASS BASELINE
-----------------------

Training class counts:

    No  = 10
    Yes =  8

The majority class is No.

BASELINE RULE
-------------

    Predict No for every customer.

BASELINE TEST RESULTS
---------------------

+------+--------+---------------------+----------------------+
| ID   | Actual | Baseline Prediction | Result               |
+------+--------+---------------------+----------------------+
| C19  | No     | No                  | Correct — TN         |
| C20  | No     | No                  | Correct — TN         |
| C21  | Yes    | No                  | Wrong   — FN         |
| C22  | No     | No                  | Correct — TN         |
| C23  | Yes    | No                  | Wrong   — FN         |
| C24  | Yes    | No                  | Wrong   — FN         |
+------+--------+---------------------+----------------------+

BASELINE CONFUSION COUNTS
-------------------------

    TP = 0       FP = 0
    FN = 3       TN = 3

BASELINE METRICS
----------------

    Accuracy = 3 correct / 6 = 50.0%
    Recall   = 0 / (0 + 3)   = 0.0%
    F1 score = 0.0%

Precision is undefined because the baseline never predicts a positive case. In
practice, it is commonly reported as zero with an explicit warning.

WHY ACCURACY ALONE CAN MISLEAD
------------------------------

Imagine 95 of 100 customers renew. A model that always predicts Yes reaches 95%
accuracy while learning nothing about who will not renew.

Always compare class-specific errors, not only the total number correct.

[DECISION]
----------

Our learned classifier should improve substantially over this no-skill rule and
should recognize at least some Yes customers.

========================================================================================
12. STEP 7 — CHOOSE A CLASSIFICATION MODEL
========================================================================================

WHY NOT USE A STRAIGHT REGRESSION LINE DIRECTLY?
------------------------------------------------

A line can produce values below 0 or above 1:

    y-hat = b0 + b1*x

But a probability must remain between 0 and 1.

    Invalid probability region       Valid region       Invalid region
              < 0                 [0 ---------- 1]           > 1

LOGISTIC REGRESSION SOLVES THIS
-------------------------------

Despite its name, logistic regression is a classification method.

It performs two transformations:

    1. Create an unrestricted weighted score.
    2. Convert that score to a probability using the sigmoid function.

    Usage x ---> z = b0 + b1*x ---> Sigmoid(z) ---> Probability ---> Class

SIGMOID SHAPE
-------------

Probability
  1.0 |                                      ********
      |                                  ****
  0.8 |                              ****
      |                           ***
  0.5 |-----------------------****------------------ decision midpoint
      |                    ***
  0.2 |                ****
      |          ******
  0.0 |**********
      +----------------------------------------------------> Score z
             very negative       0       very positive

Properties:

  - a very negative score becomes a probability near 0;
  - a score of zero becomes exactly 0.50;
  - a very positive score becomes a probability near 1;
  - the curve never goes below 0 or above 1.

WHY THIS MODEL FITS OUR FIRST EXERCISE
--------------------------------------

  - binary outcome;
  - one numerical feature;
  - interpretable coefficient;
  - visible probability curve;
  - calculations can be followed manually;
  - produces both probability and class.

========================================================================================
13. STEP 8 — TRAIN LOGISTIC REGRESSION MANUALLY
========================================================================================

GOAL
----

Find b0 and b1 that give high probability to observed Yes outcomes and low
probability to observed No outcomes across the training set.

MODEL FORM
----------

    Step A — Weighted score:

        z = b0 + b1*x

    Step B — Probability:

                    1
        p = -----------------
            1 + e^(-z)

    Step C — Default class rule:

        if p >= 0.50, predict Yes
        if p <  0.50, predict No

WHAT THE LEARNING ALGORITHM MAY CHANGE
--------------------------------------

    b0 = intercept
    b1 = coefficient for weekly usage hours

The training rows stay fixed. The algorithm repeatedly adjusts b0 and b1.

----------------------------------------------------------------------------------------
13.1 UNDERSTAND LOG LOSS
----------------------------------------------------------------------------------------

The training objective needs to judge probabilities, not only final classes.

For one row:

    If actual y = 1:  loss = -ln(p)
    If actual y = 0:  loss = -ln(1 - p)

INTUITION TABLE
---------------

+----------+----------------------+---------------------+------------------+
| Actual y | Predicted p(Yes)     | Interpretation      | Approx. Log Loss |
+----------+----------------------+---------------------+------------------+
|        1 | 0.90                 | Confident correct   |            0.105 |
|        1 | 0.60                 | Correct, uncertain  |            0.511 |
|        1 | 0.10                 | Confident wrong     |            2.303 |
|        0 | 0.10                 | Confident correct   |            0.105 |
|        0 | 0.40                 | Correct, uncertain  |            0.511 |
|        0 | 0.90                 | Confident wrong     |            2.303 |
+----------+----------------------+---------------------+------------------+

The large penalty for confident mistakes discourages the model from claiming
certainty that the training evidence does not support.

----------------------------------------------------------------------------------------
13.2 THE OPTIMIZATION LOOP
----------------------------------------------------------------------------------------

    Start with candidate b0 and b1
                 |
                 v
    Calculate a probability for all 18 training customers
                 |
                 v
    Compare probabilities with actual 0/1 labels
                 |
                 v
    Calculate average log loss
                 |
                 v
    Adjust b0 and b1 in a direction that lowers loss
                 |
                 +------------------------+
                 |                        |
                 v                        |
        Loss still decreasing? ---YES-----+
                 |
                NO
                 |
                 v
       Keep the best coefficients

EXAMPLE SEARCH PROGRESS
-----------------------

+----------------+----------------+---------------------------+
| Candidate b0   | Candidate b1   | Average Training Log Loss |
+----------------+----------------+---------------------------+
|         0.0000 |         0.0000 |                    0.6931 |
|        -2.0000 |         0.1500 |                    0.5283 |
|        -3.0000 |         0.2500 |                    0.4848 |
|        -3.6799 |         0.3166 |                    0.4779 |
+----------------+----------------+---------------------------+

Lower is better. The table illustrates the purpose of optimization; software
normally performs many precise updates automatically.

----------------------------------------------------------------------------------------
13.3 LEARNED PARAMETERS
----------------------------------------------------------------------------------------

The fitted training data gives these rounded coefficients:

    b0 = -3.6799
    b1 =  0.3166

THE LEARNED MODEL
-----------------

    z = -3.6799 + 0.3166 * Weekly_Usage_Hours

                      1
    P(Renewal=Yes) = ---------
                     1 + e^(-z)

MODEL CARD
----------

    +------------------------------------------------------------------------+
    | INPUT             : Weekly usage hours                                  |
    | OUTPUT 1          : Estimated probability of renewal                    |
    | OUTPUT 2          : Predicted Yes/No class                              |
    | INTERCEPT b0      : -3.6799                                             |
    | USAGE COEFFICIENT :  0.3166                                             |
    | DEFAULT THRESHOLD :  0.50                                               |
    | TRAINING RANGE    : 2 to 19 hours                                       |
    +------------------------------------------------------------------------+

----------------------------------------------------------------------------------------
13.4 INTERPRET THE COEFFICIENT
----------------------------------------------------------------------------------------

Because b1 is positive, higher weekly usage raises the model's estimated renewal
probability.

Logistic regression coefficients act on LOG-ODDS. Converting b1 to an odds ratio:

    Odds multiplier for one extra hour = e^(0.3166)
                                       = approximately 1.372

Plain-language interpretation:

    Within this small dataset, each additional weekly usage hour multiplies the
    estimated odds of renewal by approximately 1.37, or raises the odds by about
    37% relative to the previous odds.

This does NOT mean probability always rises by 37 percentage points. Odds and
probability are different quantities.

----------------------------------------------------------------------------------------
13.5 FIND THE 0.50 DECISION BOUNDARY
----------------------------------------------------------------------------------------

The sigmoid gives probability 0.50 when z = 0.

    0 = -3.6799 + 0.3166*x

    3.6799 = 0.3166*x

    x = 3.6799 / 0.3166
      = approximately 11.62 weekly hours

At the default 0.50 threshold:

    Usage below about 11.62 hours  ---> predict No
    Usage at/above about 11.62     ---> predict Yes

BOUNDARY VISUAL
---------------

Probability
  1.0 |                              **************
      |                          ****
  0.5 |---------------------X---------------------- threshold
      |                 ****  11.62 hours
  0.0 |*****************
      +------------------------------------------------> Usage hours
        2          7          12          17         20

The boundary is a consequence of BOTH the model and threshold. Changing the
threshold changes the classification boundary without retraining b0 or b1.

----------------------------------------------------------------------------------------
13.6 CALCULATE ONE PROBABILITY BY HAND
----------------------------------------------------------------------------------------

Customer with 15 weekly usage hours:

STEP 1 — CALCULATE THE SCORE
----------------------------

    z = -3.6799 + 0.3166 * 15
      = -3.6799 + 4.7490
      =  1.0691                    (small difference from rounding is normal)

Using the more precise coefficient gives z approximately 1.0684.

STEP 2 — APPLY SIGMOID
----------------------

              1
    p = ----------------
        1 + e^(-1.0684)

    e^(-1.0684) is approximately 0.3437

              1
    p = -------------
        1 + 0.3437

    p = approximately 0.7443

STEP 3 — APPLY THRESHOLD
------------------------

    0.7443 >= 0.50, therefore predict Yes.

IMPORTANT
---------

The model says approximately 74.4% probability, not "this customer will certainly
renew." In the dataset, the 15-hour customer C14 actually did not renew.

========================================================================================
17. CHOOSING A CLASSIFICATION THRESHOLD
========================================================================================

THE MODEL AND THE DECISION ARE SEPARATE
---------------------------------------

    Trained model ---> Probability ---> Threshold policy ---> Yes/No action

Changing a threshold does not retrain the probability model.

DEFAULT THRESHOLD
-----------------

    p >= 0.50 ---> Yes
    p <  0.50 ---> No

But 0.50 is a convention, not a universal law.

LOWER THRESHOLD
---------------

    More customers become predicted Yes.
    Recall usually rises.
    False positives usually rise.
    Precision may fall.

HIGHER THRESHOLD
----------------

    Fewer customers become predicted Yes.
    Precision usually rises.
    False positives usually fall.
    Recall may fall.

TEST-SET ILLUSTRATION
---------------------

+-----------+----+----+----+----+----------+-----------+--------+--------+
| Threshold | TP | TN | FP | FN | Accuracy | Precision | Recall | F1     |
+-----------+----+----+----+----+----------+-----------+--------+--------+
|      0.30 |  3 |  1 |  2 |  0 |    66.7% |     60.0% | 100.0% |  75.0% |
|      0.50 |  3 |  2 |  1 |  0 |    83.3% |     75.0% | 100.0% |  85.7% |
|      0.80 |  2 |  3 |  0 |  1 |    83.3% |    100.0% |  66.7% |  80.0% |
+-----------+----+----+----+----+----------+-----------+--------+--------+

Two thresholds can have the same accuracy but very different business behavior.

THRESHOLD DECISION TREE
-----------------------

                         What matters more?
                                |
                 +--------------+--------------+
                 |                             |
                 v                             v
       Avoid missing Yes cases       Avoid false Yes predictions
                 |                             |
                 v                             v
        Consider lower threshold      Consider higher threshold
        Emphasize recall              Emphasize precision

BUSINESS COST EXAMPLE
---------------------

Suppose predicting Yes means the company does not send a retention offer.

    False Positive:
    Customer predicted Yes, actually No.
    Cost may be a lost subscription.

    False Negative:
    Customer predicted No, actually Yes.
    Cost may be an unnecessary discount.

If a lost subscription costs much more than an unnecessary discount, the company
might define the positive class as "will not renew" or lower the action threshold
for retention risk. The target definition must match the decision being supported.

[CRITICAL]
----------

Choose thresholds using validation data and documented business costs. Do not
search the final test set repeatedly for the threshold that looks best.

========================================================================================
19. WHAT THE MODEL LEARNED — AND DID NOT LEARN
========================================================================================

WHAT IT LEARNED
---------------

  - renewal probability generally increases with weekly usage;
  - the learned coefficient is positive;
  - the 0.50 boundary is around 11.62 weekly hours;
  - each extra hour multiplies estimated renewal odds by about 1.37;
  - historical outcomes contain overlap and uncertainty.

WHAT IT DID NOT LEARN
---------------------

The model does not know:

  - subscription price;
  - customer satisfaction;
  - plan type;
  - length of customer relationship;
  - number of support issues;
  - team size;
  - competitor offers;
  - whether a customer can afford renewal;
  - why any individual customer made a decision.

ASSOCIATION IS NOT CAUSATION
----------------------------

The model observes:

    higher usage <---- associated with ----> more renewals

It does not prove:

    forcing extra usage ---- causes ----> renewal

Hidden factors might influence both usage and renewal.

PROBABILITY IS NOT CERTAINTY
----------------------------

    P(Yes) = 0.74

means an estimated tendency for comparable customers. A single customer's final
outcome is still either Yes or No.

INTERPOLATION VERSUS EXTRAPOLATION
----------------------------------

Training range: 2 to 19 hours.

    14.5 hours ---> interpolation; supported by nearby examples
    30 hours   ---> extrapolation; beyond observed training range

Although sigmoid still returns a number for 30 hours, that number is not strong
evidence that the real-world relationship remains valid there.

MODEL BOUNDARY
--------------

    DATA understands historical rows.
    MODEL summarizes a pattern in those rows.
    THRESHOLD translates probability into a decision.
    BUSINESS PROCESS decides what action, if any, follows.

These four layers should not be confused.

========================================================================================
20. IMPROVING THE CLASSIFICATION SYSTEM
========================================================================================

1. COLLECT MORE REPRESENTATIVE DATA
-----------------------------------

Twenty-four customers are useful for teaching, not for production. More historical
periods and customer segments reduce uncertainty and enable reliable validation.

2. ADD FEATURES AVAILABLE BEFORE RENEWAL
----------------------------------------

Possible inputs:

  - plan type;
  - subscription age;
  - recent usage trend;
  - number of active days;
  - customer-support interactions;
  - feature adoption;
  - payment failures;
  - customer satisfaction score.

Every feature must have a clear definition, collection time, and business reason.

3. USE TIME-AWARE EVALUATION
----------------------------

For a future prediction, training on earlier months and testing on later months is
often more realistic than randomly mixing all dates.

    Earlier customers ---> Train
    Later customers   ---> Test future behavior

4. CHECK CLASS IMBALANCE
------------------------

If only a small fraction belongs to one class:

  - do not rely on accuracy alone;
  - inspect precision, recall, and class counts;
  - consider appropriate sampling or weighting during training;
  - preserve the real class distribution in final evaluation.

5. TUNE THE THRESHOLD TO THE ACTION
-----------------------------------

Choose a threshold from error costs and validation performance. A model may support
several actions with different thresholds:

    very low renewal probability ---> human retention review
    medium probability            ---> no automatic action
    very high probability         ---> planning estimate only

6. CHECK PROBABILITY CALIBRATION
--------------------------------

Group many predictions into probability bands and compare predicted with observed
rates.

    Predicted around 20% ---> did roughly 20% renew?
    Predicted around 70% ---> did roughly 70% renew?

7. ANALYZE ERRORS BY SEGMENT
----------------------------

Overall performance can hide weaker results for:

  - countries;
  - plan types;
  - new versus long-term customers;
  - small versus large organizations;
  - accessibility or demographic groups where legally and ethically appropriate.

8. MONITOR AFTER DEPLOYMENT
---------------------------

    New data ---> Predictions ---> Outcomes arrive ---> Compare ---> Investigate
                                                            |
                                                            v
                                                   Retrain if justified

Monitor:

  - input distributions;
  - missing-value rates;
  - class balance;
  - accuracy, precision, recall, and calibration;
  - changes in customer behavior;
  - changes in product or pricing;
  - fairness and adverse impacts.

9. KEEP A HUMAN REVIEW PATH
---------------------------

Especially for uncertain or high-impact cases, allow humans to review context the
model does not contain.

========================================================================================
21. COMMON BEGINNER MISTAKES
========================================================================================

MISTAKE 1 — CONFUSING PROBABILITY WITH CLASS
---------------------------------------------

Wrong: "The model output is Yes."

Better: "The model output is 0.713 probability; the 0.50 policy converts it to Yes."

MISTAKE 2 — USING THE ANSWER AS AN INPUT
----------------------------------------

Using Renewal_Label, payment-after-renewal, or future account status creates
leakage and unrealistic performance.

MISTAKE 3 — EVALUATING ON TRAINING DATA ONLY
--------------------------------------------

Training performance measures fit to known examples, not generalization.

MISTAKE 4 — REPEATEDLY LOOKING AT THE TEST SET
----------------------------------------------

Every test-driven adjustment leaks information from the test into development.

MISTAKE 5 — REPORTING ACCURACY ALONE
------------------------------------

Accuracy can appear high while the model ignores an important class.

MISTAKE 6 — NOT NAMING THE POSITIVE CLASS
------------------------------------------

Precision and recall are ambiguous unless the report states what "positive" means.

MISTAKE 7 — ASSUMING 0.50 IS ALWAYS THE RIGHT THRESHOLD
------------------------------------------------------

The right threshold depends on business costs, capacity, and validation evidence.

MISTAKE 8 — TREATING 0/1 AS NUMERICAL MAGNITUDES
------------------------------------------------

The distance between class labels is not a measured quantity. The labels name
categories.

MISTAKE 9 — EXPECTING PERFECT SEPARATION
----------------------------------------

Real classes overlap because inputs are incomplete and outcomes contain noise.

MISTAKE 10 — IGNORING DATA COLLECTION TIME
-------------------------------------------

An input available after renewal cannot support a prediction made before renewal.

MISTAKE 11 — BELIEVING CORRELATION PROVES CAUSATION
--------------------------------------------------

Usage may signal customer value, but the classifier does not prove that increasing
usage causes renewal.

MISTAKE 12 — TRUSTING PROBABILITIES OUTSIDE THE TRAINING RANGE
--------------------------------------------------------------

The equation can calculate them, but historical support may be absent.

MISTAKE 13 — ROUNDING TOO EARLY
-------------------------------

Use precise coefficients during calculation and round only displayed results.

MISTAKE 14 — FORGETTING THE BASELINE
------------------------------------

A complex model that does not beat a simple rule has not demonstrated value.

MISTAKE 15 — TURNING A PREDICTION DIRECTLY INTO AN AUTOMATIC ACTION
-----------------------------------------------------------------

Prediction, policy, human judgment, and customer treatment are separate concerns.
