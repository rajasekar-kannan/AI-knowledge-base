1. INTRODUCTION AND PURPOSE
========================================================================================

WHAT IS MACHINE LEARNING?
-------------------------

Machine Learning (ML) creates software that learns patterns from examples.

TRADITIONAL PROGRAMMING:                 MACHINE LEARNING:

    +-------+   +-------+                   +-------+   +---------+
    | DATA  | + | RULES |                   | DATA  | + | ANSWERS |
    +---+---+   +---+---+                   +---+---+   +----+----+
        +-----------+                           +------------+
                    |                                        |
                    v                                        v
               +---------+                              +---------+
               | ANSWERS |                              |  MODEL  |
               +---------+                              +----+----+
                                                            |
                                      New Data --------------+
                                                            v
                                                      +------------+
                                                      | PREDICTION |
                                                      +------------+

EXAMPLE — SPAM EMAIL
--------------------

Traditional rule: IF subject contains "FREE MONEY" THEN spam

ML approach:

    10,000 labeled emails ---> Learn word patterns ---> Predict new email

WHY FOUNDATIONS FIRST?
----------------------

A library can execute model.fit(), but it cannot decide:

  - whether your target represents the real problem;
  - whether future information leaked into training;
  - whether accuracy is misleading;
  - whether the model memorized noise;
  - whether the result is safe or fair enough to use.

THE BIG PICTURE:

    GOOD PROBLEM  +  GOOD DATA  +  VALID EVALUATION  +  SUITABLE MODEL
          |              |               |                    |
          +--------------+---------------+--------------------+
                                         |
                                         v
                              RELIABLE ML APPLICATION

*** IMPORTANT: The algorithm is only one part of an ML system. ***

----------------------------------------------------------------------------------------
3.1 LINEAR ALGEBRA
----------------------------------------------------------------------------------------

A) SCALARS, VECTORS, MATRICES, TENSORS [M]
----------------------------------------

SCALAR               VECTOR                    MATRIX
One value            One ordered list          Rows x Columns

  28.5               [1200, 3, 10]             +-------------------+
 temperature         area  rooms age            | 1200   3   10     |
                                               |  900   2   25     |
                                               | 1800   4    5     |
                                               +-------------------+

TENSOR = multidimensional array

  Grayscale image: Height x Width
  Color image    : Height x Width x RGB Channels

ML DATA SHAPES:

    X = Feature Matrix  -> (samples, features)
    y = Target Vector   -> (samples,)

Example:

             FEATURES (X)                    TARGET (y)
       +------------------------+          +-----------+
       | Area | Rooms | Age     |          | Price     |
       +------+-------+---------+          +-----------+
       | 1200 |   3   |  10     |  ---->   | 300,000   |
       |  900 |   2   |  25     |  ---->   | 210,000   |
       +------------------------+          +-----------+

B) SHAPE AND TRANSPOSE [M]
--------------------------

    X = 3 samples x 2 features            X^T = 2 features x 3 samples

       [1  2]                                  [1  3  5]
       [3  4]       ---- transpose ---->       [2  4  6]
       [5  6]

WHY IT MATTERS: Most NumPy/ML errors are incompatible-shape errors.

C) DOT PRODUCT [M]
-----------------

    Features x = [2, 3]
    Weights  w = [4, 5]

    x . w = (2 x 4) + (3 x 5) = 23

ML CONNECTION:

    prediction = w1*x1 + w2*x2 + ... + wn*xn + bias

                  +------+       +---------+
    Features ---->| DOT  |------>| Weighted|----> Prediction
    Weights  ---->|PRODUCT|      |  Sum    |
                  +------+       +---------+

D) MATRIX MULTIPLICATION [M]
-----------------------------

    X (samples x features)  @  W (features x outputs)
                         =  predictions (samples x outputs)

    (100 x 5)  @  (5 x 3)  =  (100 x 3)

INNER DIMENSIONS MUST MATCH:

         (100 x [5])  @  ([5] x 3)
                  \_________/
                    MATCH!

E) DISTANCE AND MAGNITUDE [M]
-------------------------------

Euclidean distance:

    d(a,b) = sqrt((a1-b1)^2 + (a2-b2)^2 + ...)

                  y
                  |
             b *  |     distance
                \ |
                 \|
                  * a
                  +---------------- x

USED BY: KNN, K-Means, SVM (indirectly), similarity calculations

WHY SCALING MATTERS:

    Age range    : 18 to 80
    Salary range : 20,000 to 2,000,000

Without scaling, salary dominates the distance calculation.

F) EIGENVALUES AND EIGENVECTORS [R]
------------------------------------

An eigenvector is a direction that does not rotate during a transformation.
The eigenvalue tells how much that direction stretches or shrinks.

    Original direction ---- Matrix transform ----> Same direction, new length

ML CONNECTION: PCA uses these ideas to find directions with maximum variance.

PRACTICAL EXERCISES:
  1. Create a 3x2 NumPy array; print shape and transpose.
  2. Calculate a dot product by hand, then verify with np.dot().
  3. Multiply a (2x3) matrix by a (3x2) matrix.
  4. Compare KNN distance before and after feature scaling.

3.2 PROBABILITY AND STATISTICS
----------------------------------------------------------------------------------------

IMPORTANCE LEVEL: [========= ] CRITICAL — Data understanding and evaluation

A) POPULATION VS SAMPLE [M]
---------------------------

    +---------------------------------------------------+
    | POPULATION: Every customer you care about         |
    |                                                   |
    |   o o o o o o o o o o o o o o o o o o o o       |
    |             +-------------+                       |
    |             | SAMPLE      |                       |
    |             | o o o o o   |                       |
    |             +-------------+                       |
    +---------------------------------------------------+

Population parameter: true unknown population property
Sample statistic     : value calculated from observed data

CRITICAL QUESTION: Does your sample represent future production users?

B) DESCRIPTIVE STATISTICS [M]
-----------------------------

Data: [2, 3, 3, 4, 100]

  Mean     = 22.4   <-- pulled strongly by outlier 100
  Median   = 3      <-- middle value; robust to outliers
  Mode     = 3      <-- most frequent
  Range    = 98
  Variance = average squared spread from mean
  Std Dev  = square root of variance (original unit)
  IQR      = 75th percentile - 25th percentile

VISUAL:

    2  3  3  4                                           100
    *--*--*--*---------------------------------------------*
          ^                                                ^
        median                                           outlier

C) PROBABILITY BASICS [M]
--------------------------

Probability scale:

    0.0 ------------------- 0.5 ------------------- 1.0
 impossible                uncertain                certain

Rules:

    P(not A)    = 1 - P(A)
    P(A and B)  = joint probability
    P(A | B)    = probability of A, GIVEN B occurred

Example:

    P(spam | contains_link)
       ^             ^
       |             +-- evidence
       +---------------- outcome of interest

D) COMMON DISTRIBUTIONS [M]
----------------------------

  BERNOULLI       BINOMIAL        NORMAL/GAUSSIAN        POISSON
  yes/no          count successes continuous bell        event count
  churn?          7 wins/10       height, noise          calls/hour

Normal distribution:

 Frequency
    |
    |                   .-''''-.
    |                .-'        '-.
    |              .'              '.
    |_____________/________|__________\____________> Value
                           mean

68-95-99.7 RULE [R]:

      <---- 99.7% ---->
         <-- 95% -->
            <-68%->
    -----|----|----|----|----|----|-----
        -3s  -2s  -1s   mean +1s +2s +3s

E) COVARIANCE VS CORRELATION [M]
---------------------------------

CORRELATION RANGE:

   -1.0                    0.0                    +1.0
    |-----------------------|-----------------------|
 strong negative       no LINEAR relation      strong positive

Positive:                     Negative:                  Near zero:

 y |       *                  y | *                      y |  *   *
   |    *                       |   *                      | *  *
   |  *                         |      *                   |    *  *
   |*                           |         *                | *
   +------ x                    +------ x                  +------ x

*** CORRELATION DOES NOT IMPLY CAUSATION. ***

F) SAMPLING BIAS [M]
--------------------

    Real Population                      Biased Sample
 +---------------------+              +----------------+
 | Young  Old  Rural   |              | Mostly young   |
 | Urban  New  Loyal   | --- bad ---> | urban users    |
 | Churned Active ...  |              +----------------+
 +---------------------+

COMMON BIASES:
  - Selection bias    : some groups are systematically excluded
  - Survivorship bias : only remaining/successful cases are observed
  - Temporal bias     : old data no longer represents today
  - Measurement bias  : groups measured differently
  - Class imbalance   : important class is rare

G) BAYES' THEOREM [R]
----------------------

                         P(evidence | cause) x P(cause)
    P(cause | evidence) = -------------------------------
                                  P(evidence)

FLOW:

    Prior Belief + New Evidence ---> Updated Belief (Posterior)

Example: A medical test result must be interpreted with the disease base rate.

H) CONFIDENCE INTERVALS AND HYPOTHESIS TESTS [N]
-------------------------------------------------

Confidence interval: plausible range around an estimate.

                  estimate
                     |
    <----------------*---------------->
        lower bound       upper bound

A p-value is NOT the probability that a hypothesis is true.
Statistical significance is NOT automatically practical importance.

PRACTICAL EXERCISES:
  1. Calculate mean, median, standard deviation, and IQR.
  2. Plot a histogram and explain center, spread, skew, and outliers.
  3. Build a correlation matrix and state two limitations.
  4. Calculate a conditional probability from a 2x2 table.

3.3 CALCULUS AND OPTIMIZATION
----------------------------------------------------------------------------------------

IMPORTANCE LEVEL: [=======   ] HIGH — Essential intuition for model training

A) FUNCTIONS [M]
----------------

    Input x  --->  f(x)  --->  Output y

An ML model is a function with adjustable parameters (weights).

B) DERIVATIVE = SLOPE [M]
-------------------------

    y
    |                         /
    |                      __/   Positive slope
    |                _____/
    |__________ ____/____________________________ x
               ^
          near-zero slope

Derivative asks: "If x changes slightly, how much does y change?"

C) PARTIAL DERIVATIVES AND GRADIENTS [R]
-----------------------------------------

For many weights:

    Gradient = [dLoss/dw1, dLoss/dw2, ... dLoss/dwn]

Each value says how the loss changes when one weight changes.

D) LOSS FUNCTIONS [M]
---------------------

Loss = numerical measure of prediction error.

Regression — Mean Squared Error:

    MSE = average((actual - prediction)^2)

Classification — Log Loss:

    confident wrong prediction ---> LARGE penalty
    confident correct prediction -> small penalty

E) GRADIENT DESCENT [M]
-----------------------

    Loss
      |
      |  o Start
      |   \
      |    o
      |      \
      |       o
      |         \___o Minimum
      +-------------------------------- Weight

UPDATE RULE:

    new_weight = old_weight - learning_rate x gradient

TRAINING LOOP:

    +------------+     +-----------+     +----------+
    | Predict    | --> | Calculate | --> | Compute  |
    | with model |     | loss      |     | gradient |
    +------------+     +-----------+     +----+-----+
         ^                                      |
         |                                      v
         +---------- Repeat <------------- Update weights

F) LEARNING RATE [M]
--------------------

    TOO SMALL              GOOD                 TOO LARGE
    . . . . . .            o                    o---->
    slow progress           \                   <----o
                             o                  oscillates/
                              \__ minimum       diverges

PRACTICAL EXERCISES:
  1. Plot y = x^2 and identify positive/negative slope regions.
  2. Implement gradient descent for y = x^2.
  3. Compare tiny, suitable, and excessive learning rates.

5.1 DATA TYPES AND STRUCTURES

TYPES OF DATA IN ML:

+----------------------+-------------------------+------------------------------+
| Type                 | Examples                | Typical Handling             |
+----------------------+-------------------------+------------------------------+
| Numeric continuous   | age, salary, temperature| scale/transform if needed    |
| Numeric discrete     | rooms, purchases        | use directly or bin carefully|
| Categorical nominal  | city, color             | one-hot/other encoding       |
| Categorical ordinal  | low, medium, high       | order-aware encoding         |
| Date and time        | purchase timestamp      | extract safe time features   |
| Text                 | reviews, emails         | tokenize/vectorize           |
| Time series          | prices, sensor readings | preserve chronology          |
| Image                | photos, scans           | pixel arrays/features        |
+----------------------+-------------------------+------------------------------+

*** Stored dtype is not semantic meaning: ZIP code 600001 is categorical. ***

DATASET ANATOMY:

    +----------------------------------------------------+-------------+
    | FEATURES (X)                                       | TARGET (y)  |
    +--------------+-----------+-----------+-------------+-------------+
    | area         | rooms     | age       | city        | price       |
    +--------------+-----------+-----------+-------------+-------------+
    | 1200         | 3         | 10        | Chennai     | 300000      |
    +--------------+-----------+-----------+-------------+-------------+
       one row = one observation / sample / prediction unit

DATA STRUCTURES:

  Tabular     : rows and columns (most classical ML)
  Sequential  : ordered text, events, time series
  Spatial     : images, maps, video
  Graph       : connected entities (networks, molecules)

TARGET DEFINITION [M]:

Before modeling, complete this sentence:

    "For each __________ at time __________, predict __________ within
     __________ using only data available by __________."

Example:

    "For each active customer at month-end, predict cancellation within
     30 days using only data available by month-end."

----------------------------------------------------------------------------------------
5.2 DATA PREPROCESSING AND CLEANING
----------------------------------------------------------------------------------------

IMPORTANCE LEVEL: [==========] CRITICAL — Most practical ML effort happens here

THE DATA-CLEANING PIPELINE:

    +---------+    +---------+    +----------+    +-------+    +---------+
    | RAW DATA|--->| VALIDATE|--->| MISSING  |--->| TYPES |--->| OUTLIERS|
    +---------+    | SCHEMA  |    | VALUES   |    +-------+    +----+----+
                   +---------+    +----------+                       |
                                                                   v
    +---------+    +-----------+    +----------+    +-----------+  |
    | READY   |<---| SCALE     |<---| ENCODE   |<---| DUPLICATES|<-+
    | DATA    |    | IF NEEDED |    | CATEGORIES|   +-----------+
    +---------+    +-----------+    +----------+

A) SCHEMA AND VALIDITY [M]
--------------------------

CHECK:
  - expected columns and data types;
  - allowed ranges and categories;
  - unique IDs and duplicate keys;
  - impossible values (age = -5);
  - inconsistent units (kg versus pounds);
  - join multiplication and unmatched records.

B) MISSING VALUES [M]
---------------------

    Missing value found
            |
       [Why missing?]
        /     |      \
     Error  Random  Informative
       |       |        |
    Correct  Impute   Add missing flag /
    source   or drop  treat as category

COMMON STRATEGIES:

  Numeric     : median (robust), mean, model-based imputation
  Categorical : mode or explicit "Unknown"
  Row/Column  : remove only with a justified threshold and impact review

*** Fit imputation values on TRAINING DATA ONLY. ***

C) DUPLICATES [M]
------------------

    Exact duplicate   ---> may overweight one observation
    Near duplicate    ---> may leak across train/test split
    Repeated entity   ---> may require GROUPED splitting

Do not delete blindly; first define what makes a real-world record unique.

D) OUTLIERS [M]
---------------

    Most values                                  Outlier
    * * ** * *** ** *------------------------------*

AN OUTLIER MAY BE:
  - input error;
  - wrong unit;
  - rare but valid case;
  - the important event you are trying to predict.

OPTIONS: correct, remove with reason, cap, transform, robust-scale, or retain.

E) CATEGORICAL ENCODING [M]
-----------------------------

NOMINAL (no order):

    Color       Red   Blue   Green
    Red    --->  1      0      0
    Blue   --->  0      1      0

ORDINAL (real order):

    Low ---> 0     Medium ---> 1     High ---> 2

WARNING: Do not give nominal categories arbitrary numbers and imply an order.

F) FEATURE SCALING [M]
-----------------------

STANDARDIZATION:

    z = (x - training_mean) / training_standard_deviation

REQUIRES/BENEFITS FROM SCALING:          USUALLY DOES NOT REQUIRE SCALING:

  KNN, K-Means, SVM, PCA                  Decision Trees
  regularized linear/logistic             Random Forest
  neural networks                         Gradient-boosted Trees

G) DATA LEAKAGE [M — CRITICAL]
--------------------------------

LEAKAGE = training uses information unavailable at real prediction time or
information from validation/test data.

    WRONG:
    ALL DATA ---> Impute/Scale/Select ---> Split ---> Inflated evaluation

    CORRECT:
    ALL DATA ---> Split ---> Fit transforms on TRAIN ---> Apply to VALID/TEST

COMMON LEAKS:
  - using final status to predict an earlier event;
  - scaling/imputing before splitting;
  - duplicates or the same customer in train and test;
  - random split for future prediction;
  - choosing features using test performance.

GOLDEN RULE: SPLIT FIRST. FIT LEARNED TRANSFORMATIONS ON TRAINING DATA ONLY.

H) EXPLORATORY DATA ANALYSIS — EDA [M]
---------------------------------------

    SCHEMA --> TARGET --> MISSING --> DISTRIBUTIONS --> RELATIONSHIPS --> LEAKAGE

QUESTIONS TO ANSWER:
  1. What does one row mean?
  2. Is the target reliable and balanced?
  3. Which values are missing, invalid, duplicated, or extreme?
  4. Do subgroups or time periods behave differently?
  5. Could any feature reveal the answer unfairly?

5.3 FEATURE ENGINEERING
----------------------------------------------------------------------------------------

IMPORTANCE LEVEL: [========  ] HIGH — Exposes useful patterns to the model

WHAT IS IT?
Creating informative features from existing data.

    Raw Data ----------------> Engineered Feature
    birth_date                age_at_prediction
    price + area              price_per_square_unit
    transaction history       purchases_last_30_days
    timestamp                 hour, weekday, is_weekend

TECHNIQUES:

1. MATHEMATICAL TRANSFORMATIONS
   - log transform       : reduce skew in positive values
   - polynomial feature : represent curves
   - ratios              : price/area, debt/income

2. DATE/TIME FEATURES
   - year, month, hour, day_of_week
   - is_weekend, is_holiday
   - days_since_last_event

3. TEXT FEATURES
   - word/character counts
   - TF-IDF
   - embeddings [N]

4. AGGREGATION FEATURES
   - purchases_last_30_days
   - average_order_value
   - time_since_previous_event

5. INTERACTION FEATURES
   - height and weight -> BMI
   - feature1 * feature2

FEATURE-SELECTION DECISION:

    [Candidate Feature]
            |
    Available at prediction time? -- NO --> REMOVE (leakage)
            |
           YES
            |
    Legal, ethical, and permitted? -- NO --> REMOVE/REVIEW
            |
           YES
            |
    Stable and useful in validation? -- NO --> REMOVE/SIMPLIFY
            |
           YES
            v
          KEEP

PIPELINE ARCHITECTURE:

    Raw Row -> Imputer -> Encoder -> Scaler -> Model -> Prediction

PRACTICAL EXERCISES FOR DATA:
  1. Perform EDA and create a data-quality report.
  2. Compare three missing-value strategies using cross-validation.
  3. Implement StandardScaler logic, then verify with scikit-learn.
  4. Create five domain-based features without future leakage.
  5. Build a ColumnTransformer + Pipeline for mixed data types.

6.2 MODEL TRAINING PIPELINE
----------------------------------------------------------------------------------------

THE COMPLETE ML WORKFLOW:

 +--------+   +--------+   +--------+   +--------+   +--------+   +--------+
 | DEFINE |-->| COLLECT|-->| CLEAN &|-->| SPLIT  |-->| TRAIN  |-->|EVALUATE|
 | PROBLEM|   | DATA   |   | PREP   |   | DATA   |   | MODEL  |   | MODEL  |
 +--------+   +--------+   +--------+   +--------+   +--------+   +---+----+
                                                                        |
                                                                        v
                                                               +----------------+
                                                               | DEPLOY/MONITOR |
                                                               +----------------+

STEP 1 — FRAME THE PROBLEM [M]
------------------------------

Define prediction unit, target, prediction time, allowed features, horizon,
error costs, latency, success metric, safety, and privacy constraints.

STEP 2 — CREATE A BASELINE [M]
--------------------------------

    Regression     : predict training mean/median
    Classification : predict majority class
    Time series    : predict previous value

COMPLEX MODEL MUST BEAT A MEANINGFUL BASELINE.

STEP 3 — SPLIT DATA [M — CRITICAL]
-----------------------------------

                         ALL LABELED DATA
              +------------------+------------------+
              |                  |                  |
              v                  v                  v
       +--------------+   +--------------+   +--------------+
       | TRAINING SET |   | VALIDATION   |   | TEST SET     |
       | Fit model +  |   | Compare/tune |   | Final check  |
       | preprocessing|   | decisions    |   | Use once     |
       +--------------+   +--------------+   +--------------+

CHOOSE SPLIT BY DATA STRUCTURE:

  Independent rows    -> Random split
  Imbalanced classes  -> Stratified split
  Same users/devices  -> Group split
  Predicting future   -> Chronological split

*** Test data must NEVER influence training or tuning decisions. ***

STEP 4 — TRAIN VS TUNE [M]
---------------------------

    PARAMETERS (learned)                 HYPERPARAMETERS (chosen/tuned)
    linear coefficients                  tree depth
    tree split thresholds                regularization strength
    cluster centroids                    number of neighbors K

STEP 5 — CROSS-VALIDATION [M]
--------------------------------

    Fold 1: [VALID][TRAIN][TRAIN][TRAIN][TRAIN]
    Fold 2: [TRAIN][VALID][TRAIN][TRAIN][TRAIN]
    Fold 3: [TRAIN][TRAIN][VALID][TRAIN][TRAIN]
    Fold 4: [TRAIN][TRAIN][TRAIN][VALID][TRAIN]
    Fold 5: [TRAIN][TRAIN][TRAIN][TRAIN][VALID]

    Final score = average validation performance across folds

Preprocessing must be fitted INSIDE each training fold (use a Pipeline).

STEP 6 — ERROR ANALYSIS [M]
---------------------------

    Aggregate metric
          |
          +--> Confusion matrix / residuals
          +--> Worst errors
          +--> Errors by subgroup
          +--> Errors by time period
          +--> Probability/threshold behavior
          +--> Label-quality inspection

----------------------------------------------------------------------------------------
6.3 EVALUATION METRICS
----------------------------------------------------------------------------------------

IMPORTANCE LEVEL: [==========] CRITICAL — Measure what the real decision needs

A) REGRESSION METRICS [M]
-------------------------

+----------+-----------------------------+---------------------------------------+
| Metric   | Meaning                     | Use / Caution                         |
+----------+-----------------------------+---------------------------------------+
| MAE      | average absolute error      | interpretable; less outlier-sensitive |
| MSE      | average squared error       | heavily penalizes large errors        |
| RMSE     | square root of MSE          | target units + large-error penalty     |
| R^2      | improvement over mean       | may be negative on test data           |
| MAPE     | percentage error            | fails near actual value zero           |
+----------+-----------------------------+---------------------------------------+

RESIDUAL:

    residual = actual - predicted

Good residual plot: random cloud around zero.

 residual
    +     *   *  *
  0 +--*---*-----*---*-------------------- predicted
    +      *   *    *

Pattern in residuals ---> model missed structure / changing variance / outliers.

B) CLASSIFICATION CONFUSION MATRIX [M]
---------------------------------------

                              PREDICTED
                         Positive    Negative
                    +-------------+-------------+
    ACTUAL Positive | TP correct  | FN missed   |
                    +-------------+-------------+
           Negative | FP alarm    | TN correct  |
                    +-------------+-------------+

C) CLASSIFICATION METRICS [M]
--------------------------------

    Accuracy  = (TP + TN) / ALL
    Precision = TP / (TP + FP)    "When I predict positive, am I correct?"
    Recall    = TP / (TP + FN)    "How many real positives did I find?"
    F1        = harmonic mean of Precision and Recall

WHEN TO PRIORITIZE:

    False positives costly? ---> PRECISION (unnecessary investigation/action)
    False negatives costly? ---> RECALL    (missed disease/fraud/safety issue)
    Rare positive class?    ---> PR-AUC + Precision/Recall, not accuracy alone

WHY ACCURACY CAN FAIL:

    100 transactions: 99 legitimate + 1 fraud
    Model predicts ALL legitimate

    Accuracy = 99%              Fraud Recall = 0%
    Looks excellent             Completely useless

D) DECISION THRESHOLD [M]
-------------------------

    Probability: 0.0 ------------------------------------------- 1.0
                      ^ default 0.5

    Lower threshold  -> more positives -> recall usually rises, precision may fall
    Higher threshold -> fewer positives -> precision may rise, recall usually falls

Choose threshold using VALIDATION data and real error costs.

E) ROC-AUC, PR-AUC, CALIBRATION [R]
------------------------------------

  ROC-AUC : ranking across thresholds; can look optimistic for rare positives
  PR-AUC  : precision/recall tradeoff; useful with imbalanced positive class
  Calibration: among predictions near 0.8, about 80% should be positive

METRIC SELECTION FLOW:

    BUSINESS DECISION -> ERROR COSTS -> METRIC -> THRESHOLD -> MONITORING

----------------------------------------------------------------------------------------
6.4 OVERFITTING, UNDERFITTING, AND REGULARIZATION
----------------------------------------------------------------------------------------

IMPORTANCE LEVEL: [==========] CRITICAL — #1 practical modeling problem

THE CORE PROBLEM:

 UNDERFITTING                GOOD FIT                    OVERFITTING
 (High Bias)                (Balanced)                  (High Variance)

 y |  *    *                y |       ****             y | *  * *
   | *  ---  *                |    ***    ***             |  */\/\**
   |    *                     |  **          **           | */ * \ *
   +---------- x              +------------- x            +---------- x

 Too simple                  Captures pattern             Memorizes noise
 Train error HIGH            Train error LOW              Train error VERY LOW
 Valid error HIGH            Valid error LOW              Valid error HIGH

HOW TO DETECT:

    Training poor + Validation poor   ---> UNDERFITTING
    Training good + Validation poor   ---> OVERFITTING
    Both good and close               ---> PROMISING FIT

TRAINING CURVES:

 Error
   |\
   | \                   Validation error
   |  \____           ___/
   |       \_________/
   |   \__________________ Training error
   +----------^------------------------------- Epochs
              |
         best validation point / early stopping

REGULARIZATION — CONTROLS COMPLEXITY:

  L1 (Lasso)      : adds |weights| penalty; some weights can become zero
  L2 (Ridge)      : adds weights^2 penalty; shrinks all weights smoothly
  Elastic Net     : combines L1 + L2
  Tree controls   : max_depth, min_samples_leaf
  Early stopping  : stop when validation performance worsens

MODEL DEBUGGING DECISION TREE:

                         Model performs poorly?
                                  |
                  +---------------+----------------+
                  |                                |
          Training error HIGH             Training LOW, Valid HIGH
                  |                                |
            UNDERFITTING                       OVERFITTING
                  |                                |
       +----------+----------+          +----------+-----------+
       | More useful features|          | More representative  |
       | Better model class  |          | data                  |
       | Less regularization |          | More regularization  |
       | Fix optimization    |          | Simpler model        |
       +---------------------+          | Feature selection    |
                                        +----------------------+

FIRST CHECK BOTH SIDES FOR DATA LEAKAGE AND BAD SPLITS.

----------------------------------------------------------------------------------------
6.5 BIAS-VARIANCE TRADEOFF
----------------------------------------------------------------------------------------

BIAS     = model assumptions are too simple -> systematic error
VARIANCE = model is too sensitive to the exact training sample

THE TRADEOFF:

 Error
   |\  Bias
   | \
   |  \                Total Error
   |   \            ___/\___
   |    \__________/       \
   |         _________ Variance
   |      __/
   +------------------^----------------------> Model Complexity
   Simple          Sweet Spot                 Complex
   High Bias                                  High Variance

PRACTICAL IMPLICATIONS:
  - start with a simple baseline;
  - increase complexity only when validation evidence supports it;
  - compare training and validation performance;
  - stop when additional complexity harms generalization.

7. SUPERVISED LEARNING ALGORITHMS
========================================================================================

IMPORTANCE LEVEL: [========= ] CRITICAL — Know purpose, intuition, and tradeoffs

----------------------------------------------------------------------------------------
7.1 REGRESSION ALGORITHMS
----------------------------------------------------------------------------------------

A) LINEAR REGRESSION [M]
------------------------

CONCEPT: Find the best straight line/plane through data.

    y_hat = b0 + b1*x1 + b2*x2 + ... + bn*xn

VISUAL — STUDY HOURS -> SCORE:

 Score
   |                  *
   |              *  /
   |           *    /       Best-fit line
   |        *      /
   |     *       /
   |  *        /
   +-------------------------------- Study Hours

HOW IT LEARNS:
  1. Make predictions with coefficients.
  2. Calculate error (often MSE).
  3. Adjust coefficients to reduce error.
  4. Repeat or solve directly.

ASSUMPTIONS / CHECKS:
  - relationship approximately linear in specified features;
  - residuals reasonably independent;
  - residual variance approximately stable;
  - strong multicollinearity can destabilize coefficients;
  - influential outliers can distort the line.

STRENGTHS: fast, interpretable, excellent baseline.
LIMITATION: cannot naturally learn complex nonlinear patterns.

B) POLYNOMIAL REGRESSION [R]
-----------------------------

Adds x^2, x^3, or interaction features.

 y |         *
   |      *     *
   |    *         *       Curved pattern
   |  *
   +---------------- x

Higher degree ---> more flexibility ---> greater overfitting risk.

C) RIDGE, LASSO, ELASTIC NET [M]
---------------------------------

    LINEAR MODEL + PENALTY

    Ridge (L2)       -> shrink coefficients
    Lasso (L1)       -> shrink; some become zero
    Elastic Net      -> combine L1 and L2

Scale numeric features before interpreting regularized coefficients.

D) TREE-BASED REGRESSION [R]
-----------------------------

Decision Tree      : nonlinear rules; easy to overfit
Random Forest      : averages many trees; stable baseline
Gradient Boosting  : trees correct previous errors; strong tabular performance

REGRESSION EXERCISE:

    Mean Baseline -> Linear -> Ridge/Lasso -> Tree -> Random Forest
           |             |          |          |          |
           +-------------+----------+----------+----------+
                                      |
                              Compare MAE/RMSE + residuals

----------------------------------------------------------------------------------------
7.2 CLASSIFICATION ALGORITHMS
----------------------------------------------------------------------------------------

A) LOGISTIC REGRESSION [M]
--------------------------

Despite its name, it is used for CLASSIFICATION.

    Features ---> Linear score z ---> Sigmoid ---> P(class = 1)

SIGMOID:

 Probability
  1.0 |                 ______
      |              __/
  0.5 |-------------*---------------- threshold
      |          ___/
  0.0 |_________/
      +-------------------------------- z

Example — spam:

    z = 2.5*has_free + 1.8*has_urgent + 3.0*has_offer + bias
    P(spam) = sigmoid(z)
    IF P(spam) >= chosen_threshold ---> SPAM

STRENGTHS: fast, interpretable, probability output, excellent baseline.
LIMITATION: default boundary is linear unless features are transformed.

B) K-NEAREST NEIGHBORS — KNN [M]
---------------------------------

INTUITION: "Tell me who your neighbors are; I will classify you similarly."

Visual (K=3):

       O O O           X X X
       O O               X X
       O    ? <--- new point
         O O           X
       O              X X

3 nearest: 2 O, 1 X ---> predict O

CHOOSING K:

    K too small ---> sensitive to noise / overfit
    K too large ---> boundary too smooth / underfit

MANDATORY: scale features; validate K rather than relying on a fixed rule.

C) DECISION TREES [M]
----------------------

INTUITION: A flowchart of questions leading to a decision.

                         [Income > 50K?]
                          /           \
                       YES             NO
                       /                \
              [Credit > 700?]      [Guarantor?]
                 /       \           /       \
               YES       NO        YES       NO
                |         |          |         |
            [APPROVE] [REVIEW]   [APPROVE] [REJECT]

HOW IT LEARNS:
  - test candidate feature thresholds;
  - choose the split reducing impurity most;
  - repeat until stopping rules.

IMPURITY: Gini or Entropy.

STRENGTHS: nonlinear, handles interactions, no scaling needed.
LIMITATION: deep trees are unstable and overfit.

D) RANDOM FOREST [R]
---------------------

    [Tree 1] [Tree 2] [Tree 3] [Tree 4] ... [Tree N]
       A        B        A        A               A
       |        |        |        |               |
       +--------+--------+--------+---------------+
                            |
                   MAJORITY VOTE = A

WHY IT WORKS:
  - trees see different row samples;
  - splits see random feature subsets;
  - individual trees make different errors;
  - averaging reduces variance.

KEY HYPERPARAMETERS: n_estimators, max_depth, min_samples_leaf, max_features.

E) SUPPORT VECTOR MACHINE — SVM [R]
------------------------------------

CONCEPT: Find the separating boundary with maximum margin.

  Class O                 |                 Class X
    O O                   |                   X X
  O O                     |                     X X
    O       <--- margin --|-- margin --->     X
  O O                     |                   X X
                          ^
                    decision boundary

Closest points are SUPPORT VECTORS.

KERNELS [N]: Linear, Polynomial, RBF for nonlinear boundaries.
Scaling is important. SVM can work well on medium/high-dimensional data.

F) NAIVE BAYES [R]
-------------------

Uses Bayes' theorem and assumes features are conditionally independent.

    Words in email ---> P(words | spam) x P(spam) ---> P(spam | words)

Fast and often effective for bag-of-words text classification.

G) GRADIENT-BOOSTED TREES [R]
------------------------------

    Tree 1 errors ---> Tree 2 corrects ---> Tree 3 corrects ---> Final sum

Common libraries: XGBoost, LightGBM, CatBoost.
Strong for tabular data; requires careful validation and regularization.

CLASS IMBALANCE [M]:

    Stratify split -> Select metrics -> Class weights/resampling TRAIN only
                    -> Tune threshold -> Inspect minority errors

CLASSIFICATION EXERCISE:
Build a spam/churn classifier and compare:

    Dummy -> Logistic Regression -> Decision Tree -> Random Forest

Report confusion matrix, Precision, Recall, F1, PR-AUC, chosen threshold, and
five important failure cases.

IMPORTANCE LEVEL: [=======   ] HIGH — Find structure without target labels

----------------------------------------------------------------------------------------
8.1 CLUSTERING
----------------------------------------------------------------------------------------

A) K-MEANS CLUSTERING [M]
--------------------------

ALGORITHM:
  1. Choose K clusters.
  2. Initialize K centroids.
  3. Assign each point to nearest centroid.
  4. Move each centroid to its group's mean.
  5. Repeat 3-4 until stable.

VISUAL — K=2:

 Step 1: Initialize             Step 2: Assign

   * *  o  *       o *           [* * o *]       [o *]
 *   *  *            *           [*   * *]       [  *]

 Step 3: Move centers          Step 4: Final clusters

   [* * O *]      [o *]          Cluster A       Cluster B
   [*   * *]      [  O]          left group      right group

 O/o = centroids, * = observations

CHOOSING K — ELBOW METHOD:

 Inertia
    |\
    | \
    |  \___
    |      \________  <--- diminishing improvement
    +----|----|----|----|---------------- K
         1    2    3    4
                   ^ possible elbow

LIMITATIONS:
  - K required in advance;
  - assumes compact, roughly spherical clusters;
  - sensitive to scaling, initialization, and outliers;
  - cluster IDs have no inherent business meaning.

B) HIERARCHICAL CLUSTERING [R]
-------------------------------

Builds a hierarchy shown as a dendrogram.

 Distance
    |
    |              +-----------+
    |        +-----+-----+      |
    |     +--+--+     +--+--+   |
    |     A     B     C     D   E
    +--------------------------------

Agglomerative: each point starts alone; merge nearest groups.
Divisive     : one large group; split recursively.

C) DBSCAN [R]
--------------

Groups dense regions and labels isolated observations as noise.

    ****                 ***
   ******      x         *****        x = noise
    ****                  ***

STRENGTH: irregular cluster shapes; K not required.
LIMITATION: parameter-sensitive; difficult with varying densities.

CLUSTER VALIDATION:

    Internal metric + Stability + Domain meaning + Useful action
                           |
                           v
                   TRUSTWORTHY SEGMENTS

----------------------------------------------------------------------------------------
8.2 DIMENSIONALITY REDUCTION
----------------------------------------------------------------------------------------

A) PCA — PRINCIPAL COMPONENT ANALYSIS [M]
-------------------------------------------

GOAL: Replace correlated features with fewer directions capturing high variance.

Original axes:                        Principal axes:

 y |       .....                         PC2 /
   |    .......                              /
   |  ......                         PC1 ---/-------------->
   +------------- x

    50 features ---> PCA ---> 10 components ---> retain most variance

IMPORTANT:
  - scale when feature units differ;
  - components mix original features and reduce interpretability;
  - choose count using explained variance + validation;
  - fit PCA on training data only in predictive workflows.

B) t-SNE AND UMAP [N]
----------------------

Useful for nonlinear 2D/3D visualization. Attractive gaps do NOT prove true
clusters; parameters and random seed can change the picture.

UNSUPERVISED EXERCISE:
Scale customer features, compare K-Means and DBSCAN, create a PCA 2D plot, then
justify whether the segments are stable, interpretable, and actionable.
